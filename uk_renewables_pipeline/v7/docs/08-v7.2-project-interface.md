# V7.2 project-interface acceptance matrix

Status: **specification only; V7.1 remains live**. This document decides the next build before any interface code changes. The executable mirror is `contracts/projects-plugin.v7.2.json`.

## Product and engineering comparison

| Sector | Preserve from working V5/V7.1 | Use from V6/V7.2 spine | Deliberate V7.2 result |
|---|---|---|---|
| Shell and mobile | Newspaper-first layout, filters, searchable table, CSV, mobile table scroll | Same-origin validated assets | Keep visual language and responsive behavior; change only controls and fields required by canonical projects |
| Project universe | Utility-scale solar/BESS intent | Canonical REPD/GG identity and Q2 reconciliation | 384 solar `>49 MWp` plus 382 BESS `>99 MW`; 766 records, 718 developments, no wind |
| Analytics | Counts, capacity and largest-project gauges | Official technology and capacity | Four gauges: solar MWp, BESS MW, project records and largest filtered project; never add solar MWp to BESS MW |
| Identity | Search and row-level interaction | REPD Ref, GG project ID and evidence-backed development ID | Keep every REPD record distinct; expose and search all three identities |
| Lifecycle | Official status filter | Official status, derived lifecycle and milestone dates | All 766; Current 670; Disputed 3; Historical 63; Review 30. Derived lifecycle is labelled, never presented as a replacement for REPD status |
| Geography | County filter and Atlas link | Canonical nullable coordinates and GeoJSON | Keep all records in JSON; GeoJSON contains valid geometry only. V7.2 validates map readiness; interactive map remains V7.7 |
| Newspaper | 125-story feed, seven controls and independent failure behavior | V6 separation of official and article facts | Newspaper code and decisions stay byte-for-byte unchanged; any project-row signal is labelled external legacy intelligence — unverified |
| Search | Site/operator search | Canonical IDs, planning and relationship fields | Search site, operator, REPD/GG IDs, planning reference/authority, geography and related refs |
| Table/evidence | Capacity-descending rows and external news links | Canonical facts and provenance | Add REPD Ref, GG project ID and planning reference to the primary table; retain development, dates, relationships, geometry and provenance as accessible evidence |
| Export | UTF-8 BOM CSV of displayed projects | Canonical identity and units | Export only current filtered rows; a zero-result filter produces a header-only file, never all projects |
| Reliability | Projects and newspaper can fail separately | Same-origin data, geometry-nullability and last-known-good discipline | Project JSON failure cannot falsify gauges; GeoJSON failure cannot empty the table; newspaper failure cannot erase projects |

## Exact acceptance values

- All: 766 records across 718 developments.
- Solar: 384 records, 34,073.49 MWp; largest solar record 840 MWp.
- BESS: 382 records, 106,338.18 MW; largest BESS record 1,450 MW.
- Lifecycle partition: Current 670 + Disputed 3 + Historical 63 + Review 30 = 766. The groups are disjoint.
- This edition has 766 valid geometries and zero missing, but the interface must support missing and invalid geometry without deleting a record.
- V5 newspaper: 125 articles = 69 solar + 56 BESS; finance filter 34. These are parity fixtures, not proof of canonical binding.

## Canonical interaction sentinels

| Query | Required result |
|---|---|
| `13599` | One record: Beacon Fen solar, REPD 13599 |
| `GG2050-REPD-13599` | One record: Beacon Fen solar, REPD 13599 |
| `GG2050-DEV-E13842D4D80DEC` | Two distinct records: Beacon Fen solar 13599 and BESS 13600 |
| `EN010151` | The same two distinct Beacon Fen records |
| `Beacon Fen` | The same two distinct Beacon Fen records |

An exact REPD Ref or GlobalGrid project ID takes precedence over relationship-context search, so querying `13599` does not also return a co-located component merely because its development references solar record 13599.

No component may be merged merely to simplify display. Relationship targets outside the 766-record threshold universe remain valid context and must not fail or manufacture an in-scope row.

## Known V5/V7.1 flaws fenced by this contract

- The current loader consumes legacy GeoJSON, filters at 1 MW and discards canonical identity.
- Wind controls remain visible and the gauges combine incompatible technologies.
- Search covers only site and operator; table/export omit canonical identity, planning evidence and lifecycle.
- Zero filtered results currently export every project.
- The project table directly calls the inherited newspaper matcher, coupling canonical facts to unverified legacy intelligence.
- Chart.js is unpinned and the declared plugin manifest is not enforced by the host. These are recorded risks; dependency/host changes are not smuggled into V7.2 unless required by its approved implementation.

## Build and promotion boundary

The present `--phase spec` gate proves the contract, data and unchanged V7.1 baseline. It does **not** claim V7.2 is live. The later approved interface build must make `--phase integrated` pass, advance the visible label and manifest once, then validate a fresh checkout of the exact remote commit and the deployed production bytes.

V7.3 alone replaces news identity and event decisions. V7.4–V7.9 remain exactly as governed by the README.
