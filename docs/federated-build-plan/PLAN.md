GlobalGrid2050 owns public publication and composition. Pipeline News and GridAtlas core reliability comes first; optional commercial layers must not block core apps. The programme contains 50 planned increments for each app, not 100 completed releases.

Publish only tested, pinned products with their source/engine identities, exact served-byte checks and scoped Chrome/CI evidence. Preserve historical versions and documented failures. A documentation or navigation update is not a product promotion. The locally staged2028 candidate remains unpublished and is not included in this change.

Keep original V6 chart UI intact; its federation belongs in gb-electricity-ui, with proven data products from data-gb-electricity and data-interconnectors. Do not reactivate monolith API collectors or copy archives into this publication repository. Weekly ingestion belongs to confirmed data owners and retains source interval semantics.

Before moving YAML or Python, confirm its destination repository and record pinned workflow/script/import/input/environment/output closure in the Spider graph. No migration is authorized merely by a plan entry. Preserve the straight-line engine first pass and adjacent Claude/Codex work.

Before homepage edits, follow homepage_versions/README.md: run the restore-point measurement workflow, record a numbered snapshot before editing, retain all app/version links, then verify served bytes. Use an isolated worktree from current remote main and stage only owned files.

For restart, read this repository's AGENTS.md and the canonical programme. Recheck Git status, branch, current pointers and CI; dated handovers are evidence checkpoints rather than proof of current state. Next product work requires the current user request and one bounded meaningful change with rollback to a known tested release.
