# News transition-context disclosure

This isolated future-V9.29 component consumes SUPPORT's
`globalgrid2050.transition-context.v1` export inside an existing News host.
It does not mount a separate dashboard, select a release, fetch sources,
crosswalk projects, or change the News collector. No formal application is wired
to it in this increment.

The accepted exporter and typed-renderer identities are in `pins.json`.
Composer authored commit `1cc0c919ba13a55f5217365b6abe8d3dba89ec29` and its
unchanged producer dependency chain are separate prerequisite commits. See
[`../TRANSITION_CONTEXT.md`](../TRANSITION_CONTEXT.md) for producer dependency
identities, input receipts, field semantics and bounded coverage. The fixture is
generated by that real CLI during tests, not hand-written. Its accepted SHA-256
is `de0d205186ae2a30914711e1b25bacefc325f7c02efb880e4d5d5a6c070a87c1`:
14 records (8 policy, 2 grid, 4 solar), 3 numeric claims, 0 linked projects.
Policy evaluations remain 7 UNKNOWN and 1 REPORTED_PROGRESS.

## Integration contract

Import `renderContext` from `render.mjs`, supply exact export bytes as a
`Uint8Array`, and inject `buildViewModel` and `renderFigures` from ADDITIONAL's
TestCode PR23 `sandbox/filings-ui` at the pin in `pins.json`. Load `context.css`
and that renderer's `figures.css`. The renderer is reused, not copied; no second
number formatter or quantity contract exists here. Each quantity has its own
adjacent role and qualifier, so an upper bound cannot silently become an exact
amount. The injected model checks FIGURES and entity identity before mounting.

```js
// host is an existing element inside News, explicitly opted in by its owner.
host.setAttribute('data-news-context-host', '');
await renderContext(host, bytes, {
  expectedSha256: acceptedManifest.transitionContextSha256,
  figures: {buildViewModel, renderFigures},
});
```

The host owns acquisition, the accepted SHA-256 manifest, pinned module loading,
and any serving/publication decision. Never read `expectedSha256` from the
untrusted payload or calculate it from downloaded bytes as an acceptance rule.
Tests deliberately rehash mutated fixtures only to exercise structural guards.
The adapter requires the host's pin, caps input at 16 MiB and 3,000 rows, checks
family/count/scope/state/receipt consistency, and delegates every figure to the
existing model. It is a consumer boundary, not another complete producer
validator or a source-truth verifier. SHA-256 matching establishes accepted
export identity, not independent factual verification.

The adapter and returned root's `contextReport` preserve every complete native
record and input receipt, including exact identifiers, hashes and producer
limitations. User-facing source and history details use readable labels rather
than JSON. Transport/schema identifiers are not presented; figures use only the
injected renderer, without a second numerical rendering in history details.
The disclosure preserves revision history, nulls and
producer metadata. It distinguishes publication, review, retrieval, evaluation
and figure clocks. Rejected amendments stay rejected; historical forecasts
stay forecasts; portfolio access never becomes site allocation. Null values
display as Unknown. COP31 background remains IN_PROGRESS with missing original
bytes and retrieval explicitly unknown; no extra commitment or outcome is
invented. Source evidence and native history are nested disclosures. The
component inherits the News host's font and colors, including the immutable
V9.24 `202611161244` theme. Scoped overrides flatten the external renderer's
light cards and enlarged amount typography while retaining quantities and
provisional status text. It introduces no numerical rank, priority or score
badges. Full-page comparison and formal integration remain with COMMAND.

Only this component's direct child root is replaced. Existing host buttons and
listeners survive. Failed updates clear stale quantities and contexts. A later
request supersedes an earlier pending digest. All text uses `textContent`;
source links require conservative public HTTPS DNS URLs without credentials or
custom ports and open with `noopener noreferrer`. Unsupported URLs fail closed.
This narrow UI intentionally does not support IP-literal source URLs.

## Reproduce checks

Use Node 24+, repository Python with the unchanged producer modules, the pinned
external TestCode renderer, and Playwright with installed Chrome. No dependency
installation, live source fetching, or production access is required.

```powershell
$env:FIGURES_UI_DIR = '<TestCode checkout>/sandbox/filings-ui'
node --test automation/news/context-ui/adapter.test.mjs
$env:PLAYWRIGHT_MODULE = '<existing Playwright installation>/index.mjs'
$env:CONTEXT_UI_ARTIFACTS = '<explicit local proof directory>'
node automation/news/context-ui/browser.mjs
```

The test helper verifies all three reused renderer file hashes before import
and checks actual exporter bytes against the accepted fixture digest. Browser
proof uses installed headless Chrome at 375/768/1440 px. Playwright fulfills
whitelisted module and actual-exporter bytes at a loopback origin; there is no
HTTP server and every unlisted request is blocked. This avoids the workstation's
observed socket-exhaustion failure without claiming served-byte verification.
Outputs are screenshots and
`proof.json` in the explicitly named artifact directory, never a release folder.
The harness checks keyboard disclosure, exact figures, scope/qualifier/history
text, escaped markup, source links, stale-result removal, host control identity,
request ordering and horizontal overflow. This is component proof, not live
release acceptance, Android testing, or source factual verification.
